# [SCENARIO.md] 분산형 데이터 연합컴퓨팅 플랫폼 PoC 실전 시연 시나리오
(PoC Demo & Verification Scenario)

본 문서는 **데이터 활용 강화를 위한 분산형 데이터 연합컴퓨팅 플랫폼**의 핵심 기능적 흐름을 실증하고 데모 발표 시 활용할 수 있는 **5단계 완결형 실전 시연 시나리오**입니다.

---

## 1. 데모 시나리오 개요 (Scenario Overview)

본 시나리오는 서로 협력 관계인 의료/바이오 사일로 3곳에서 민감한 데이터셋의 직접적인 외부 전송 없이, 로컬 격리 구역 내에서 데이터를 정제하고 중앙 제어부의 FedAvg 알고리즘에 따라 연합 학습을 완수하는 과정을 다룹니다.

* **참여 주체**:
  * **중앙 오케스트레이터(FCP)**: 데이터 과학자(DS)가 배포 및 라운드를 제어하는 제어 타워.
  * **사일로 1, 2, 3**: 독립된 데이터셋을 MinIO에 탑재하고 있는 격리 연산 노드.
* **가상 데이터 시나리오**: 환자 검진 이력 데이터(결측치 존재)를 이용한 질병 예측 협합 인공지능 모델 학습.

---

## 2. 실전 시나리오 5단계 (Step-by-Step Demo Flow)

```
[1단계] 사일로 데이터 격리 확인 ➡️ [2단계] 로컬 데이터 전처리 정제 ➡️ [3단계] 연합 학습(FedAvg) 라운드 기동 ➡️ [4단계] 글로벌 모델 섀도우 배포 ➡️ [5단계] 실시간 KPI/드리프트 관제
```

### 1단계: 사일로 데이터 물리 격리 검증 (Data Isolation Check)
* **목적**: 데이터 소유권자가 자신의 원시 데이터가 사일로 바깥(중앙 서버)으로 전송되지 않음을 검증합니다.
* **시연 절차**:
  1. 각 사일로의 내장 오브젝트 스토리지(MinIO) 콘솔(`http://localhost:7002`, `7004`)에 접속하여 로컬 데이터셋(`raw_patients.csv`)이 업로드되어 있음을 확인합니다.
  2. 중앙 FCP 백엔드에서 사일로의 스토리지 데이터에 직접 다이렉트 파일 조회를 시도했을 때, 네트워크 수준 및 스토리지 접근 정책에 의해 읽기가 거부(`403 Forbidden` 또는 접속 불가)되는 장면을 시연합니다.
* **기대 효과**: **"데이터는 오직 로컬 보안 구역(샌드박스) 내부의 스토리지에 격리되어 안전하다"**는 완벽한 격리성 입증.

---

### 2단계: 분산 데이터 원격 정제 실행 (Data Preprocessing & Cleaning)
* **목적**: 분산된 원격 데이터의 스키마를 정합하고 결측치/이상치를 안전하게 정제합니다.
* **시연 절차**:
  1. 중앙 대시보드 UI에서 **[정제 레시피 정의]** 탭으로 이동합니다.
  2. 다음의 결측치 및 이상치 필터 가이드를 JSON 규격으로 작성하여 등록합니다.
     ```json
     {
       "recipe_name": "의료데이터_결측치_보간_레시피",
       "operations": [
         {"target_column": "age", "action": "impute_mean"},
         {"target_column": "bp", "action": "filter_outliers", "threshold": 3.0}
       ]
     }
     ```
  3. 사일로 그룹(Silo 1~3)을 타겟으로 **[정제 Job 배포]**를 트리거합니다.
  4. 각 사일로 내부에서 백그라운드로 작동하는 데이터 정제 배치 잡이 완수되어 정제 정확성(KPI 2번 지표) 수치가 화면에 업데이트되는 것을 보여줍니다.

---

### 3단계: 연합 학습 라운드 및 파라미터 수집 (FedAvg Training Round)
* **목적**: 3개 사일로와 글로벌 가중치를 교환하여 인공지능 모델을 완성합니다.
* **시연 절차**:
  1. FCP 대시보드 **[연합 학습 제어]** 탭으로 이동합니다.
  2. 연합학습 라운드를 `10 Round`로 지정하고 가중 평균(FedAvg)을 활성화한 후 **[학습 시작]**을 클릭합니다.
  3. **실시간 라운드 관제**:
     * 대시보드 화면상에서 `Silo-1`, `Silo-2`, `Silo-3` 순서대로 가중치가 수집(Success)되고 라운드 진행 게이지바가 부드러운 애니메이션과 함께 상승하는 장면을 시연합니다.
     * 라운드 완료마다 중앙 FCP에서 로컬 가중치를 FedAvg 공식에 맞춰 집계하고 글로벌 모델($w_{t+1}$)을 자동 갱신하는 갱신 로그를 대시보드 하단 로그 뷰어에 표시합니다.

---

### 4단계: 신규 글로벌 모델 섀도우 배포 (Shadow Deployment)
* **목적**: 실서비스 환경에 부하 및 예측 실패 위험 없이 안전하게 신규 연합모델의 신뢰도를 검증합니다.
* **시연 절차**:
  1. 학습이 완료된 글로벌 모델을 **[모델 가입소(Registry)]**에 버전 `v1.2.0`으로 자동 패키징해 등록합니다.
  2. 운영 노드로 신 버전을 배포할 때, 기존 버전(`v1.1.0`)을 그대로 둔 상태에서 **[섀도우 배포(Shadow)]** 방식을 지정합니다.
  3. 실시간으로 들어오는 추론 요청이 구 버전과 신 버전에 복제되어 공급되며, 신 버전의 예측 정확도가 구 버전 대비 향상되는 비교 그래프를 섀도우 배포 모니터링 화면에서 시연합니다.

---

### 5단계: 실시간 KPI 및 모델 드리프트 관제 (Monitoring & Dashboard)
* **목적**: 비동기 I/O를 통해 끊김 없이 메트릭을 관제하고 데이터 드리프트 발생 시 경고하는 성능을 입증합니다.
* **시연 절차**:
  1. **5대 KPI 시각화 관제**:
     * 연합 학습 시간 추이, 데이터 정제 정확도, 통신 오버헤드, 리소스 효율성, 모델 성능 추이를 화려한 차트 라이브러리(Line/Gauge)로 화면에 표출합니다.
  2. **드리프트 경고 및 A/B 테스트 대응**:
     * 특정 사일로(예: Silo-3)의 환자 데이터 분포가 급변하여 모델 드리프트율(Drift Rate)이 경고선(Threshold: 0.15)을 초과하는 시나리오를 연출합니다.
     * 대시보드 상단에 붉은색 **[모델 드리프트 경고 알림]**이 노출되고, 연구원은 이를 통해 A/B 테스트 비율을 조정하거나 즉각 롤백을 제어하는 관리 역량을 선보입니다.
